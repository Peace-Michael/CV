Big Data & Cloud Computing – Azure Medallion Pipeline

Designing and implementing a scalable cloud-based big data processing solution for the USDA Branded Food Products dataset (1.99M records, 2.6GB) using Microsoft Azure.

1. Data Ingestion and Storage

1.1 Types and Sources of Data

The USDA Branded Food Products dataset demonstrates the core characteristics of big data through its volume (1.99M records, 2.6GB), variety (structured, categorical, textual), and velocity (monthly updates).

1.2 Cloud-Based Storage Solution

The dataset was uploaded into the Bronze Layer container within Azure Blob Storage. Storage configuration: Standard performance tier, Locally Redundant Storage (LRS), Hot tier.

Figure 2: Raw USDA dataset uploaded to the Bronze Layer in Azure Blob Storage

1.3 Data Ingestion Process

The ingestion workflow involved downloading the CSV files from USDA, uploading to Azure Blob Storage, then accessing via Apporto VM with Jupyter Notebook.

Figure 3: Data ingestion in Jupyter Notebook showing successful load

Challenges: Large file size (1.7GB) required chunk-based reading; mixed data types required explicit dtype specification.

Metric: Total data ingested: 2.6GB across 3 CSV files, processing time < 5 minutes.

2. Scalable Processing Architecture

2.1 Architecture Design

The architecture follows the Medallion Architecture (Bronze, Silver, Gold layers) using Azure Blob Storage and Python/pandas within the Apporto VM.

Figure 7: Proposed Cloud-Based Big Data Processing Workflow Using Microsoft Azure

LayerPurposeTechnologies Used
Bronze (Raw)Immutable raw dataAzure Blob Storage, CSV files
Silver (Cleaned)Filtered, cleaned, validated dataPython/pandas in Jupyter
Gold (Aggregated)Business-level aggregatespandas aggregations, matplotlib

2.2 Distributed Processing Considerations

Although Apache Spark on Azure Databricks is the industry standard, student subscription limitations prevented its use. The architecture is designed to scale to multi-node clusters in production.

Production Choice: Azure Databricks (Premium) with auto-scaling clusters and multi-node processing for parallel execution.

3. Data Extraction and Pre-processing

3.1 Dataset Selection

USDA Branded Food Products dataset: 1,993,975 rows, 21 columns, 928MB (branded_food.csv) + 1.7GB (food_nutrient.csv).

Figure 8: Dataset dimensions showing 1.99 million rows and 21 columns

3.2 Pre-processing Steps

Initial inspection revealed several columns with >90% missing data, which were dropped:

  • material_code (99.9%), discontinued_date (99.8%), trade_channel (98.1%), short_description (95.1%), subbrand_name (94.7%), preparation_state_code (95.1%), not_a_significant_source_of (96.0%), package_weight (56.9%)

Figure 11: Missing data analysis by column

After cleaning, the dataset was reduced from 21 to 13 columns, preserving all critical product information. Calorie data was integrated from food_nutrient.csv using fdc_id, achieving 93.1% coverage.

Figure 13: Calorie data merge results

Final cleaned dataset: 1,993,975 rows, 13 columns, uploaded to the Silver Layer.

5. Cost Optimization Strategies

Storage Tiering

TierStorage CostAccess CostBest For
HotHigherLowerFrequently accessed data
CoolMediumMediumInfrequently accessed (30+ days)
ArchiveLowestHighestLong-term retention (180+ days)

Strategy Applied: Raw CSV files in Hot tier, processed files in Cool tier, backups in Archive – estimated 50% cost savings.

Compute Optimization

  • Auto-termination: 30-minute idle timeout to prevent charges.
  • Right-sizing: 16GB/4-core configuration (saving 50% vs larger).
  • Spot instances (production): Up to 90% savings for non-critical workloads.

Total estimated cost savings: 60-70% compared to non-optimized configuration.

6. Security and Compliance

Data Classification

  • Public: Product information (brand names, categories)
  • Low sensitivity: Nutritional data (calories, ingredients)
  • Public identifier: UPC codes

Encryption and Access Control

  • Encryption at rest: Azure SSE with AES-256 (enabled by default).
  • Encryption in transit: TLS 1.2 minimum, secure transfer required.
  • RBAC: Least privilege access control (Contributor, Reader roles).
  • Apporto VM security: Browser-based access, university SSO, session isolation.
Shared Responsibility Model: While Azure provides infrastructure security, organizations remain responsible for identity governance, access configuration, and regulatory compliance.
